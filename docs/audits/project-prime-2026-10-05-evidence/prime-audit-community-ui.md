## Findings

### CU-01 — P1: default Edge Function deployment rejects the career reporter's custom credential and the client removes reports from retry

**Confirmed source/config mismatch; deployed override unverified. Confidence high.** `supabase/config.toml:1–2` disables JWT gateway verification only for community-map-ticket. `supabase/functions/career-report/index.ts:88–103` accepts an opaque 32–256-character server key, hashes it and checks the enabled reporter registry. **Impact high; operational likelihood high for deployment using checked-in config, unknown for existing production; fix risk low; effort S.** Add explicit `[functions.career-report] verify_jwt = false`, retain the handler's enabled-reporter hash lookup, and document custom credential auth. Treat transient deployment credential refusal as durable deferred/configuration state rather than silently removing an authoritative match from retry, or expose a deliberate recover/requeue operation for rejected reports.

**Regression:** run gateway + function end-to-end GET and POST using registered opaque key, unknown key, missing header and ordinary user JWT. Verify only registered reporters succeed; valid queued reports survive an auth/configuration outage and replay once fixed. Primary docs: [function configuration](https://supabase.com/docs/guides/functions/function-configuration), [function authentication](https://supabase.com/docs/guides/functions/auth). `config.toml` originated in `50265dd51` for map tickets; career-report custom bearer was not given matching config.

## Performance, cleanup and hypotheses requiring measurement

These are deliberately not promoted to confirmed user-visible bugs.

1. **Unbounded persistent map build cache**: MapBuildScheduler.cs:164–200 creates a directory and `.lock` per fingerprint; no pruning/lifetime budget found. Compiled memory cache is bounded, disk cache is not. Repeated geometry edits accumulate immutable outputs indefinitely. Add explicit disk budget/LRU eviction respecting live cross-process leases. Benchmark disk growth across1000 distinct edits, retention after restart, warm-cache latency and concurrent eviction safety. Use app-owned path abstraction for cache; Shared at :35–36 bypasses PROJECT_PRIME_USER_DATA overrides by using SpecialFolder.LocalApplicationData directly.
2. **Memory budget is a file-size budget, not a peak-memory budget**: MapPackageReader.ReadRequired :337–349 allocates declared entry-sized MemoryStream plus ToArray, so256MiB entry needs roughly512MiB transient buffers before parser/compiler allocations. ContentHash :352–366 reads each asset into an array. Builder retains all expanded entries before writing (MapPackageBuilder.cs:54–79), up to1GiB, and strict readback allocates again. Stream hashing and two-pass validation/build writing could reduce LOH/GC pressure. Benchmark peak RSS/allocated bytes/GC pause at16/64/256MiB texture entry and8 concurrent validations. Do not infer OOM without host memory measurement.
3. **Fingerprint preparation precedes bounded queue**: MapBuildScheduler.Prepare :121–125 spawns cloning/hashing in Task.Run before Schedule :64–65; many callers can create unbounded preparation work although compiler queue is bounded. Measure50 distinct1GiB requests, I/O concurrency and RSS; put preparation under a bounded/single-flight lane if observed. Current UI serializes many actions, reducing reachable risk.
4. **Prewarm skipped due busy host lane does not retry the same room**: RoomPrewarm.cs:251–256 completesfalse if host mutex unavailable; Begin :58–61 subsequently treats same room's non-null completion as already handled. A burst of independent hosted lobbies may consistently move load cost back to Start. Also model decode :320 cannot cancel after generation changes until decode completes. Measure hosted-lobby burst and map-switch/start p95 (cold vs hot) with real extracted assets before changing retry/cancel policy. JoinForLoad :172 intentionally synchronously joins, so owner-frame responsiveness depends on preparation scheduling; it is not proof of deadlock.
5. **Catalog decoration cost**: MapCreatorCatalog.Decorate :51 scans favorites for each map; at2000 maps/100k favorites this is up to200M comparisons, under shared lock. Reports/favorites copy and rewrite entire arrays on every update (:56–69). Prefer counts + per-user indexes and paged persistence; benchmark browse/list/favorite/report p95 at supported maxima before revising service limits.
6. **Community status mapping obscures transient failures**: MapCommunityServer.cs:1007–1011 returns400 for all exceptions, including remote identity timeout/5xx and local I/O. MapCommunityClient.cs:918–932 already has a503-specific outage message. Classify auth, validation, capacity, canceled/timeout and storage/transient failures; log request/correlation context without credentials. Inject identity503/diskfull/corruptmetadata and verify service+client retry semantics. This is operational hardening, not evidence of misauthenticated users.
7. **Local package validation cache uses path+size+mtime**, MapBundle's `_validated` dictionary/entry fast path. Same-length/same-mtime external mutation can preserve cache hit, and dictionary lacks eviction. Installed archives are expected immutable; strict install boundary remains sound.
