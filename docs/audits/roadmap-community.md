The map disk cache now uses `AppPaths.UserDataDirectory/map-cache` and bounds inactive content to1GiB with30day retention. Eviction and key-lease acquisition share a stable cross-process owner gate, so lock-file removal cannot create two owners of different inodes. Current publication and actively leased output directories are protected; a single protected large entry can exceed the nominal budget. Cache installation acquires the source lease and revalidates integrity before publishing. Future staging directories carry their held cache key; idle tagged staging left after a compiler crash is reclaimed, while active compiler staging is protected. Legacy untagged staging is preserved because its owner cannot be proven. Synthetic churn, warm restart, lease/eviction, and independent-scheduler tests exercise these boundaries.

Measurements justified the narrow performance changes. Strict package digest validation now streams with a reusable64KiB buffer; requested entries allocate exactly one payload array while enforcing declared size, actual size and EOF. Header/hash order stays byte compatible with deterministic existing packages. Favorite decoration uses map counts and per-user sets, rebuilt only after successful persistence. Preparation clone/hash admission shares configured compiler concurrency; queued caller cancellation happens before expensive allocation.
