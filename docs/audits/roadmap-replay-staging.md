# P04 detached replay preparation and owner publication

Production Studio and killcam opening now separates private preparation from owner-thread scene adoption. `PreparedReplaySource` owns a private playback session/reader, decoded construction checkpoint, independently retained frozen clip, and any verified custom-map installation. `ReplayPreparationJob` admits at most two preparation workers. Workers read/decompress/verify archives, parse checkpoint construction state, reposition their private readers, and download/verify/build missing exact custom-map packages. They do not construct `Scene`, restore a mutable world graph, touch GL, install generated runtime files, or register a room.

The scene owner explicitly commits any prepared package, validates the final map identity/runtime binaries, adopts the prepared reader/checkpoint, then constructs and fully restores an unpublished world. Playback warms that candidate using at most24 simulation steps and about1ms per ordinary update. `DemoPlayback` carries request generations through pending-source acceptance, owner package publication, candidate warmup and final publication. An obsolete or failed replacement keeps the previous presented world alive. Player seek generations likewise cancel obsolete detached work, retain the currently published world while preparation is pending, and publish only a completed candidate.

Initial durable checkpoints do not bypass the required origin. A worker independently opens the origin and checks exact required-origin bytes and metadata against the selected reader. Unless a later seek can prove exact equality with an origin already fully restored by the current player, the owner first constructs/restores/disposes an unpublished origin replica. Only then may it adopt an optional later checkpoint. A valid construction header with a truncated late graph is rejected even when the archive also contains a valid optional checkpoint. Optional seek checkpoint failure instead falls back to the required origin. The extra initial origin bind is intentional correctness work.

Historical v2/v3 range extraction has an explicit packet-origin compatibility contract: v4 `Clip`, recording origin0, no world capsule, and exactly one bounded file-only construction packet253. Its decoded room/mode/configuration must match metadata before map or host publication. These ranges reconstruct from the original detached construction and retain all hidden lead-in facts; nested extraction adds to that lead-in. An ordinary v4 clip missing its required world and carrying a match bootstrap is still refused. Actual asset tests compare original, extracted and nested v2/v3 worlds in synchronous and staged playback, including backward seek.

`ReplayPlaybackSession.ContinueLive(mapHash)` is a narrow bridge for a fully simulated private frozen correction: it retains decoder/world state and the exact recording frame, clears only its borrowed frozen cursor, and resumes contiguous live advancement. The caller continues to own the frozen byte lease. Canonical late authored-fire repair is implemented by the replay live-capture workstream; its private correction remains separate from the foreground world and immutable accepted records.

Cancellation and ownership checks occur before adoption and package publication. A canceled queued job never enters its decoder. Results that complete after cancellation are observed and disposed, including their reader, pooled clip bytes and private verified package snapshot. Owner disposal uses nested `finally` blocks so one cleanup exception cannot strand later owned resources. Portable desktop and Android launch callers commit the exact map before room-shell/asset construction and stop failed preparations after preserving the error.

The remaining owner budget is explicit. Scene construction, cartridge asset binding, full mutable graph restore, final runtime/map hashing, package publication and pose-stream setup remain owner work. These operations are not interruptible1ms slices and can exceed a simulation update budget. Moving them requires a broader resource/scene binding design; no GL or mutable scene work was moved to workers. `MapValidation`, `MapPublication`, `WorldConstruction` and `WorldRestore` telemetry distinguish that owner work from detached reading/decoding. Worker counters are atomic and only the registered frame owner contributes to owner-frame attribution.
