# Owner POV and director completion

This follow-up implements the remaining owner-presentation and evidence-based director work from [PR-08](pr08.md). The HD fixture correction is separately merged in [#879](https://github.com/AntiNotAnti/Project-Prime/pull/879); see [the reproduced cause and full GL acceptance](hd-charge-fix.md).

## Behavior

- Optional `.ownerpose` schema 2 adds the two native gun animation channels, group/slot bindings and fractional node sample; Hunter/weapon identity, palette, alpha and the actual first-person cosmetic shader surface/time; and source aspect. Schema 1 remains readable, unsupported/bad/absent data falls back. World/replay wire formats are unchanged. Capture remains opt-in with `PRIME_REPLAY_OWNER_CAPTURE=1`.
- Gun presentation is scoped to the draw. Animation slots, alpha, palette, node transforms/animations, material values/bindings and matrix palette are restored exactly, including failed draws. Reusable backup buffers allocate only on first use or model-size changes. Owner data never enters gameplay/receipt/movement state or checkpoints.
- Exact first-person export asynchronously prepares one immutable owner track before capturing any picture, and retains it across cold/backward segment seeks. A load completing during a draw requires another prepared picture before capture. Native detached exports retain/copy/hash the optional input in the existing private worker and validate it on retry. Missing or corrupt optional data is a stable reconstruction fallback. Vertical FOV is preserved; horizontal coverage adapts to the requested output aspect and is disclosed. No render-thread file reads were added.
- Director candidates include canonical subject POV, verified living victim POV, shoulder, chase, elevated tactical, an existing authored fixed key when available, and orbit. Center, footprint, wall-clearance and movement-sweep checks use the existing scene collision owner. Canonical POV is the fallback. Victim view temporarily selects the actual render subject/weapon/HUD and restores the watched player before simulation.
- Live continuous cinematic following has hysteresis, smoothing and a 120°/second angular limit. Seek, life, subject, form and teleport discontinuities are cuts with cleared history. Exact export uses stateless world-axis chase/tactical offsets or the canonical 0.4-radian/second orbit; preview history and output FPS cannot author a different path. Fixed/victim preview choices are not silently treated as continuous exact-export paths.
- A cancellable detached canonical decoder adds identity-bound first blood, headshot kills, life streaks, revenge, long shots, battle/team-battle lead changes and comebacks. Long shots require an authority-verified source/pose launch certificate joined to an accepted lethal impact, with a documented 30-native-world-unit threshold. A late low-health outnumbered kill requires exact authority health, roster and remaining-time evidence; it does not assert a victory. Fast movement is explicitly measured at resolution, not inferred at firing. Unsupported context, including ground-contact evidence for airborne claims, is omitted.
- Existing searchable events and manual reels are reused. Generate suggestions in both existing editors now includes verified contexts, and headless `-replayhighlights` JSON includes the source hash, proof descriptions and activity timeline. The activity score is `damage/10 + kills×20 + objectives×25`, capped at 100 per existing 600-frame window, with no sparse-window extrapolation. It measures recorded activity, not suspense.

## Bounds and compatibility

Owner tracks remain capped at 65,536 samples and four admitted loader jobs. A schema-2 record is 264 bytes (schema-1: 139); maximum file size is 17,301,580 bytes including header/checksum. At a hypothetical uninterrupted 60/240 sample/s this is 950,400/3,801,600 payload bytes per minute; those arithmetic sizes are not throughput benchmarks. Saturation is disclosed by fallback/drop behavior; no networking was added.

Context analysis is capped at two hours, 100,000 semantic/shot identities, 4,096 launch-certificate entries and 2,048 context candidates, with cancellation during decoding. Full identities and separate authority/source/visible-delivery clocks are preserved. Scores only use a complete stable roster and supported mode-specific authority score fields; ties/baselines/roster changes never fabricate a lead change. JSON contains no chat/account data. Existing manual edits are unchanged until explicit acceptance.
