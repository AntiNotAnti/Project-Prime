# PR-03: seek, export and Four Views audit

Audited against the current worktree on 2026-10-19. This slice adds focused
regression coverage; it does not change replay scheduling, saved-world formats,
packet comparison policy, export defaults, or camera rendering.

## Existing implementation reused

- `ReplayStudioComparison.Read` explicitly refuses to treat durable scene-world
  indexes as packet-only decoder baselines. It reports `IndexFallbackReason`,
  keeps `RestoredCheckpointFrame` null and scans the complete packet history.
  A capsule containing decoder state is not itself proof of packet-only parity:
  scene projection/advance and producer diagnostics differ. This strict fallback
  remains unchanged.
- **Interactive preview seek** uses `ReplayTransport` and `PassiveReplayPlayer`.
  It can restore validated memory/durable world capsules; failed restores are
  rejected and reconstruction falls back to the initial world. Warm-up/seek work
  is capped at 120 fixed steps per update, with an optional elapsed-time budget.
- **Exact export seek** currently shares that transport and world restoration
  policy. `ReplayVideoExporter` samples explicit canonical/presentation frames,
  requests one simulation step per observed world frame, rejects mismatched
  presentation samples, and restores its camera settings. Sharing this path
  must not be described as a newly proven packet-only checkpoint acceleration.
- `ReplayAuxiliaryRenderScope` owns camera matrices, world/model FOV, subject,
  frustum, preview dimensions, framebuffer, viewport, program and texture-unit
  state. Its `finally` paths restore state after auxiliary errors. Four Views
  uses the existing normal primary scene render and existing tile draws; no new
  full scene/render owner is introduced by this slice.
- `ReplayCameraPathSamples` compares both track object identity and complete key
  values before reusing its 129 position samples. These samples are a source-space
  authored curve, independent of actor life and canonical replay time. No new
  resolved-subject/camera-state interpolation cache is introduced here.

## Focused changes and verification

links the real `ReplayCameraPathSamples` implementation and checks unchanged
storage reuse, same-count endpoint edits, preservation of retained prior samples,
replacement track owners with identical keys, orientation/FOV-only edits, and
clear/empty-track reuse. These are synthetic authored curves, not GPU images.

## Acceptance still requiring execution or further work

- `ReplayDurableCheck` already compares cold/backward seeks, nested origins,
  corrupt checkpoint fallback and strict packet comparison against linear
  histories. It was inspected, not executed in this slice.
- `ReplayExportCheck` already compares repeated exports with changed cadence,
  dimensions, camera restoration and gameplay-state stability. Its image hashes
  are GPU/environment comparisons, distinct from scene/decoder hashes. It was
  inspected, not executed in this slice; a straight-through frame extraction
  oracle covering animation/particle/audio events remains unproven here.
- `ReplayWindowAcceptance.Rml97Studio` already exercises Four Views/A-B,
  canonical world stability, injected render failure recovery, repeated toggles,
  resize and seeking. No real OpenGL context was run in this slice; GPU resource
  leakage, scene teardown and alt-form acceptance remain unverified here.
- There is no separately selected exact-export reconstruction policy in this
  slice. Before claiming all PR-03 acceptance, run the asset-backed seek/export
  and GL harnesses, retain separate packet/shot/scene versus image results, and
  disable any acceleration that fails the corresponding parity checks. Do not
  update goldens to hide a decoder mismatch.
