### PR-07: Stable touch button instances and instant clips
- Reuses existing TouchSettings, Android overlay, Avalonia canvas, native RmlUi visual editor, controls.txt and DemoClip. No competing overlay or replay buffer.
- Keeps21 primary controls with deterministic IDs and unchanged legacy placement. Adds up to11 independent buttons (stable IDs1000–1010), each action/enabled/normalized position/scale. Versioned optional touch_instances_v1 records; invalid/oversized/duplicate-ID/nonfinite records fall back to usable primary controls. Old clients ignore extras and retain primary controls; future records remain separate.
- Existing Avalonia canvas supports add/duplicate/delete/reassign/select/move/pinch/resize/reset with detached Apply/Cancel. Native RmlUi extends the same32-target visual editor and staged settings rows with action, enabled and geometry plus duplicate/delete/action/toggle. Essential primary controls retain their existing locations.
- Android binds pointers to instance IDs, while action-held state lasts until the final finger releases. Clip presses use a bounded edge queue, including a complete tap between game frames; held buttons do not repeat. Existing15/30/60/120 lengths/postroll/availability gates remain authoritative. Pause/reload/rotation/reassignment clear stale holds. Overlay enumeration uses an immutable array publication so game-thread instance replacement cannot invalidate UI-thread drawing; highlights follow each actual pressed instance.
