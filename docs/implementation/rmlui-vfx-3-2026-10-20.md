## Existing rendering foundation

The current chamber is already procedural. `LauncherBackdropComposer` draws one
GLSL 1.20 full-screen pass in the existing window/context. It uses the shared
`LauncherChamberShader`, with cached program/uniform locations and explicit
release/context-loss paths. It does not load a gameplay room or a second renderer.
The composition includes recessed walls, gantries, braces, power conduits,
reflective light sweeps, seven Hunter motifs, a perspective floor grid, raised
platforms, segmented rings, low haze, shafts, dust and UI readability zones.
These are authored screen-space depth cues, not a geometric room, physical
volumetrics, shadow mapping, bloom or a depth-aware post-processing pipeline.

`LauncherStageFx` adds a generated 96×96 radial texture, halo, floor bounce,
two-foot contact darkening, side-bay telemetry, scanners, service lights and
per-Hunter motifs. Lobby ambience reads the shared formation table and occupied
pad colors. `DrawUnderHunter` precedes models; `DrawOverHunter` adds restrained
foreground air. No extra shipped texture or game-derived room imagery is needed.

`RmlUiHunterStageRenderer` renders the backdrop, engine Hunter previews,
foreground, then restores the target for RmlUi. It rejects suspended, inactive,
zero-size and gameplay-scene routes. Home preview bounds use actual RML side-rail
bounds. Lobby pad coordinates, model ground projection and label anchors use
`LauncherLobbyFormation`; occupied models render farthest first with the front
actor last. Formation previews retain separate model instances, avoiding one
instance being switched among eight Hunters every frame.

`PreviewPass` reuses the engine material submission and native idle animation.
It uses a scissored depth clear and transparent color preservation for chamber
previews. Its 60 Hz preview stepping is distinct from presentation refresh.
The removed historical `SamplePresentation` hook must not be reintroduced by
copying old code. Existing idle assets are reusable; weapon inspection, skeletal
blending and dynamic shadows have not been established by this audit.

`MenuMotionState` already blends activity/theme targets with elapsed time and
tracks occupancy, ready pulses and launch intensity. It clamps elapsed gaps over
250 ms to prevent a large resume jump. Activity and Hunter presets keep scene
assets shared. `CosmeticEffectQuality` already defines **Off, Low, Medium, High**;
an additional Ultra tier would require a demonstrated need and settings support.

The existing native theme already provides restrained color/opacity feedback and
reduced-motion rules. Earlier layout/UX work remains the baseline: stable hit
regions, readable text, existing scrolling behavior, modal focus and server-owned
ready/start/team decisions are preserved.

Lighting has a specific shared-path risk: `LauncherHunter.Draw` deliberately uses
`window.Scene` when a results screen overlays a live scene. Unconditionally
changing the shared preview light or world light uniforms can change that screen.
The chamber path's `window.HasScene` rejection alone does not protect the shared
Hunter preview implementation. A new light must be conditional on launcher
cinematic permission and restore prior renderer state even on failure. Material
albedo/recolors remain authored; environmental color belongs in lighting and
surrounding atmosphere.

The source also does not prove every platform is visually grounded for every
Hunter/aspect ratio. The formation table and per-model ground projection are a
strong starting point, but the requested framing/illumination acceptance requires
actual captures. Do not change geometry solely from an imagined visual defect.

## Platform and acceptance limits

The desktop compositor and StageFx are guarded with `!ANDROID && !MPHREAD_SERVER`;
the RmlUi stage additionally requires desktop shell/GL-smoke symbols. Sharing a
shader source declaration does not establish that Android runs this presentation.
The Android experimental local-Hunter page explicitly provides persistence with
no preview. Preserve those guards and existing Android behavior until a measured,
reduced-cost Android renderer path is implemented and physically qualified.

GPU capability, driver behavior, target hardware cost, and pixel correctness
cannot be established by reading GLSL or compiling C#. Windows SSH was unavailable
in this session; Mac fallback evidence must be labelled Mac. No Windows/Linux/
Android-device result, live multiplayer backend result, new GPU timing, CI pass,
published PR or shipped package is implied by this audit.

New repository captures must contain only procedural/synthetic material. Private
game-asset screenshots remain local evidence and must not be tracked. Preserve
small manifests and measurements rather than copying large build trees or assets
into the repository.

## Final polish and measured results

Home and Lobby have selected noninteractive luminous corner seams, stronger
hover/focus top edges on primary controls, and the existing short native surface
arrival transitions. The seams do not add layout flow, input targets or continuous
movement, and disappear under High Contrast. Existing Reduced Motion overrides
still suppress native animations. The Graphics cosmetic-quality hint now explains
its menu-atmosphere behavior and the Reduce Motion preference.

Visual review exposed an older roster defect: the flexible name button consumed
the row while automatic-width metadata collapsed, clipping READY/WAITING and
team controls. Giving the name button a zero flex basis and metadata a bounded
72dp width fixes the children while preserving every panel and row rectangle.
Across 28 native size/accessibility cases, all 224 actor rows now contain both
state and team controls. Permanent guards fail 16 of 24 checks against the old
1920×1080 CSS and pass all 24 against the candidate. The full native suite now
passes **21,394 assertions**, including 792 new roster checks, with zero document
or lifecycle failures.

Unchanged stages now reuse a cached immutable roster plan. It compares the actual
filtered slot/generation/Hunter/suit/name/ready/team/session facts, including
in-place array changes, rather than trusting revisions or array identity. It
rebuilds only when effective presentation facts change and clears on Hide.
**344 cache checks** cover 0–8 occupants, local-first order, duplicate rejection,
authority changes, identity edits and reuse. A warmed 24,000-lookup window allocates
zero bytes. This is the plan lookup boundary, not a claim that the complete
engine/UI frame never allocates.

The shader skips rotor math outside its casing and pedestal math outside
conservative bounds that include the full offset shadow and transition rings.
