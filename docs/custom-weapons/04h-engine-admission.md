# CW-04h remote engine-source admission

The developer scene has an alternative `EnableDeveloperEngineCustomCombat` entry.
Its source oracle derives certificates from real engine input observations and
canonical grant evidence. It never accepts a supplied pose certificate. Readiness
remains an explicit trusted `ICustomSourceReadiness` dependency; no packet handler,
public mode or client interface constructs that dependency yet. Native authority
`WorldIsReady`/`WorldAdmissionConfirmed` cannot prove a remote peer is ready.

A readiness context pins exact custom-ready schema/behavior/capability, frozen
manifest, bootstrap, recipient slot/generation, opening authority frame, first
permitted source frame and nonzero peer incarnation. It must be available before
source capture. Replacing a pinned context invalidates that occupant's engine
admission permanently. A later respawn cannot replace it or reset resource grants.
The future authenticated owner must derive these facts from its actual endpoint
peer/bootstrap and keep the original opening boundary immutable; this module does
not establish that network trust.

Admission requires current full owner life, frozen M7 runtime/manifest and exact
pinned bootstrap, then reads the exact source observation. Missing input stays
unavailable; known denied/conflicted/expired/prebirth input is rejected. Nonfire
intent uses the recorded permission and source world. Fire additionally requires
captured permission, current Shoot, an exact preceding source-frame release, matching
captured ACK/subframe, ACK nonzero and not future at observation or processing time,
bootstrap/time-window bounds, aim agreement and a claimed origin within 0.15 units
of the actual body+0.4 muzzle. No current player pose or native packed weapon-input
nibble substitutes for this custom source proof.

The actual emitted muzzle is checked against retained sampled-world geometry.
Missing source-world geometry waits; a blocked muzzle rejects. This is the existing
historical world-sample contract, not exact pre-projectile door-state retention.
The final emission adapter still preflights all effective rewind/fractional/catch-up
history and returns definite no-spawn before effects if it cannot serve it. Requested
ACK time remains separate from effective clamped collision time; mandatory custom
trade and one-component payment remain with CW-04f.

Timed grant observations now have a nominal lifecycle key. The typed custom reader
accepts `WeaponOwnerContext` without creating a native `ShotKey`; native callers and
native grant records keep their existing APIs. Reads are pure and never seed source
observations, advance expiry or create grants. The custom modifier snapshot requires
an exact first native input observation at the same authority frame as its first
custom engine observation. Unknown/missing ownership is unavailable, not base damage.

Granted Double evidence copies exact sequence, spawn room/incarnation, contact source
and world, and original expiry after verifying owner life, type, activation C+1,
authority expiry and source effective time. Later renewal/expiry cannot rewrite that
captured funding. Owner Double hints and optional native proof policy cannot authorize
it. Current Battle-only admission requires canonical Prime absence captured in the
same first source phase; it does not infer historical Prime from delayed current state.

The resulting certificate retains the original observation frame/body/aim/modifiers
and exact requested ACK. Reinspection immediately before emission must agree. The
ordered source journal owns magazine/cadence/reload and terminal action sequence;
this oracle neither spends ammunition nor allocates a native shot or payment.

This initial contract is deliberately limited to observed remote inputs. Local/bot
source-phase parity and recovery of missing/coalesced preceding frames remain gates.
A missing release is never invented. The existing native latest-intent slot cannot
by itself provide reliable complete source history under loss/reorder. Do not enable
custom public matches until those contracts, authenticated readiness/action transport,
reliable outcomes, reconnect/spectators and custom replay pass CW-04 acceptance.
