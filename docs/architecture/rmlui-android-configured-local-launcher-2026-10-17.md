# Opt-in Android configured-local launcher — October 17, 2026

## Bounded route and activation

The new route requires `MphReadRmlUiAndroidExperiment=true` and the initial Activity Intent boolean `projectprime.rmlui.launcher=true`. The ordinary Android launcher remains the default. A runnable native package also requires `MphReadRmlUiAndroidPackage=true` and matching native ABI libraries/assets; host-only compilation does not establish native startup. This opt-in reuses the verified APK extraction/input/session and existing in-game native Pause foundation.

After the existing startup flow reports that Home is ready, asset extraction has succeeded, and the current Activity is foreground, it retires the existing `AndroidHunterShot` preview worker before adding one scene-free `GameView`. A process-wide activation witness blocks any late preview work or replacement Activity from creating a parallel pbuffer until that view's render thread has stopped and destroyed its context. Destroyed Activity callbacks are rejected; the process-wide release is independent of Activity dispatch. A foreground/startup/activation recheck after preview retirement prevents late worker completion from activating an obsolete view.

Home, local Offline setup, arena paging/selection, and an authored local Hunter/suit picker use shared RmlUi pages, `RmlUiMenuController`, `RmlUiLauncherPages`, and `LauncherHunterChoiceController`. `ConfiguredLocal` capabilities hide and reject unsupported online, account, Studio, Adventure, training, text-search and advanced-rule actions. Current configured rule values are captured from the existing launcher rather than edited here. Hunter/suit Apply uses existing preferences with persistence rollback; Back keeps a dirty draft until Apply or explicit Discard. The Home drawer truthfully states that this route has no 3D preview. Unsupported controls cannot be revived by publisher refreshes or forged current-document actions. Desktop capabilities remain unrestricted by default.

## Same-view launch and lifetime

The Activity captures only detached room/rule values. Native initialization, controller ticks, input drain, page changes and rendering remain on the one existing `GameView` EGL thread. The Home mode has no `Scene`, simulation tick, network pump, offscreen preview or second EGL loop.

Local launch validates the copied draft asynchronously, then sends an immutable request containing its launcher lifetime, generation and full value to the UI thread. UI admission rechecks the exact view/request, foreground state and existing `StartScreen` readiness, then calls its authoritative `RmlUiLaunchOffline` method. Its existing startup, modifiers, preference persistence, orientation and window-settling path remains in control. Refused/throwing admission and pending-start cancellation explicitly retire native ownership and reset a usable existing launcher; a submitted controller cannot remain stranded.

At `BeginMatch`, room/mode/Hunter/bot values are compared with the admitted plan and the captured suit with the existing admission's committed preference. The exact request is acknowledged once. The same `GameView` transfers into `_gameView`; it is not added twice. On its EGL owner, the copied plan is exposed only after all native launcher cleanup is attempted and native shutdown succeeds. A failed shutdown consumes admission, quarantines the process native lease, and enters the existing match error/cleanup path before any Scene is built. Only then does the existing `AndroidMatch.Build` create the one Scene and normal game loop. The native Pause controller can later acquire the same process lease.

Touch/navigation/Back use the copied input queue and current surface/document witnesses. Background, focus loss, resize and surface loss retain the foundation's cancellation/release policy; no editable text or Android IME route is offered. Root Back reaches the existing exit confirmation through legacy fallback. Native errors retire all owners and use the existing launcher. Cleanup retires native input/controllers/host before surface/context destruction, including when another cleanup operation fails.

## Offline cyclic return and remaining migration

This slice now includes configured local Home → Offline/Hunter setup → existing match admission → fresh native Home → another local launch on the **same GameView/EGL owner**. Return is limited to a natively admitted Offline plan with no network/replay owner. It uses an explicit `RmlUiAndroidLocalCycle` phase/witness, EGL-owned cleanup/visual release/commit/foreground release, then an exact UI settings/reset acknowledgement before constructing fresh Launcher/Pause lifetimes. Scene absence cannot replay the old build delegate. The optional Scene constructor registration callback retains the exact candidate before NetAi/runtime/player initialization, so failed construction/build/OnLoad/prewarm and uncaught loop errors retire that candidate through the same terminal pipeline. Offline sets save slot zero before construction and does not commit inherited Adventure bootstrap bytes. Loading blocks UI reads of incomplete scene state; Back cancels through terminal cleanup. The process preview barrier remains held for the entire View. The existing cyclic EGL config requires both window and pbuffer support. Cleanup validates that exact context, reusing it surfaceless after window loss or using a bounded 1×1 temporary cleanup pbuffer. It always attempts temporary unbind/destruction and refuses fresh Home after any binding/identity/cleanup failure. No extra context, scene, window or loop is created. Stop, failed cleanup/native shutdown/foreground eligibility or refused UI reset takes terminal existing-launcher fallback. Existing direct results rematch deliberately retains its established terminal path until it has a copied local admission of its own. Human Offline recolor now uses the existing admitted `LauncherPrefs.LastColor`; bot/network/Adventure color behavior is unchanged. It does not migrate first-run setup, license/account, settings, online lobby, campaign, replay editor, results, accessibility, or a live Hunter/map preview. The world continues while the existing in-game menu is open, as documented in the [Pause route](rmlui-android-native-pause-2026-10-17.md).
