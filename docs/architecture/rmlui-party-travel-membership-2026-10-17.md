# Native Party travel and verified Social lobby membership

This slice restores the native RmlUi Party Publish, Follow, Join Leader and Decline journey over the existing Party authority and dedicated server. It does not reserve seats. A locator, a travel response and an available directory row never establish admission. The existing NetLaunch/NetSession Welcome, session and roster identity handshake still owns admission; the existing launcher join job and lobby handoff own acceptance.

## Server membership owner

`DedicatedServerSocialMembership` samples the existing dedicated peer owner after packet handling. Its witness contains the exact Peer reference, slot generation, transport connection incarnation, match ID, authority epoch, phase and opaque career ticket. The UDP server never decodes that ticket or derives a Prime ID from a display name or ClientId. `SocialLobbyMembershipRelay` sends it over HTTPS; the existing reporter credential owner adds authorization without exposing the server key.

`SocialLobbyMembershipPump` schedules at most eight concurrent requests and retains at most 64 current/retiring identities. Successful heartbeats repeat after 20 seconds, failures after five seconds. A changed phase, identity or connection sends the captured new generation after any pending request; a ticket refresh sends the old leave before its replacement heartbeat. Failed leaves retry within a bounded 90-second retirement window; membership itself has a 60-second backend TTL. Shutdown cancels workers and relies on that TTL. These are HTTP workers, not another transport pump.

Every native report carries a positive monotonic sequence, serialized as a decimal string. The sequence survives restarting the same dedicated object; a newly constructed dedicated authority uses its existing fresh authority epoch, so a new incarnation starts a separate floor. The SQL migration retains reporter/epoch/player high-water rows independently of membership expiration and legacy cleanup. A newer leave prevents a delayed older heartbeat from restoring eligibility. Floors persist; they must not be truncated by ordinary membership cleanup.

The first native epoch owner is the verified reporter credential. Existing unique reporter ownership is backfilled during migration; conflicting live old rows fail closed. Another reporter cannot steal an already bound epoch. The endpoint verifies HMAC ticket subject, client binding and expiry before the database call, and SQL rechecks enabled reporter and the signed ticket deadline after acquiring the lifecycle lock. Legacy reports without a sequence remain compatible only before any positive floor; they do not gain native reordering guarantees.

## Party and admission contract

The existing native Party controller remains the only native Party worker. Travel commands capture expected self, Party ID/revision, exact travel ID/revision and the internal account lease. The auth owner checks that lease before authentication and again after authentication, before invoking the function, so an account refresh or replacement cannot reinterpret captured work. The witness is excluded from JSON.

The new SQL wrapper takes the existing Party lifecycle lock, validates expected self and Party revision, and delegates to the restored Party/lobby functions. Publish requires the current leader's verified eligible membership and a public locator obtained from public directory plus live server facts. Publish and Clear compare the captured travel identity, so delayed work cannot overwrite or erase an intervening destination while the membership-only Party revision is unchanged. Follow, Join Leader and Decline require the exact current, unexpired travel revision. Projection and mutation recheck lobby and eligible leader membership with wall-clock time after the lock.

Follow/Join Leader return an immutable `NativePartyJoinTarget` with expected self, Party/travel revisions, lobby ID, literal public locator, protocol, epoch, room, expiry and an opaque lease. The native join service revalidates backend witnesses, requires exactly one matching directory row and a live compatible Lobby phase/epoch/room, then calls the existing join path. An active session is refused; there is no silent leave. It checks the accepted server state again before owner handoff. Party endpoint preferences are persisted only after successful existing lobby handoff.

The current status packet already embeds the existing MatchState authority epoch. `NetStatus.Describe` now projects that existing value into `ServerStatus.AuthorityEpoch`; no status bytes or protocol version changed. Unknown legacy epochs remain zero and cannot prove a native locator.

The candidate captures the exact transport, lifecycle incarnation and role it created. Every lifecycle publication shares the shared client lifecycle gate; normal frame Update remains unchanged. A unique existing client-only LobbyContext reference distinguishes successive same-valued plans, even if a caller reuses the same target. Cancellation and late failure cleanup can retire only that transport, including a failed socket candidate; a replacement session is preserved. The existing launcher job performs CanAccept, AcceptJoin and then NotePartyJoined. Once that handoff succeeds, the native service always detaches the exact ready candidate, even if auth retires at the Note boundary; later cancellation cannot tear down the accepted owner. Preference persistence and backend acknowledgement remain separately gated by current transport and auth. The final background acknowledgement requires current actual lobby ownership and server-verified actor membership in the target epoch; backend Joined is never inferred from Reserved, Following or directory presence.

The RmlUi Party page shows the verified destination, publishes the current public lobby, follows or joins the leader, and declines travel. Expired travel and retired account data clear from the owner projection. A failed root scheduling handoff is visible on the same page. No legacy UI or new reservation packets are introduced; protocol 57 is unchanged.
