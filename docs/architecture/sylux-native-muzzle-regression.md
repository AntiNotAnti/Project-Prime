Scope: October Fruity plan PR08a, separate from authority claim validation. Source baseline `ec9d63f7afa7ddd1220cf9441f619c3576294014`; Fruity reference [PR112](https://github.com/liveteklol/Fruity-Prime/pull/112). Reviewed actual Fruity `Testing/NetCombatCheckSylux.cpp` via GitHub Contents API: its native fixture selects a real room obstacle, pins gun/muzzle positions around the finite barrel interval, invokes `TryFireWeapon`, and checks owner/remote behavior separately. Prime's existing `--shot-proof-scene` validates authority proof and is not a substitute for native spawn behavior.

## Reproduction

`/Users/jarrett/.dotnet/dotnet tools/nettest/bin/Debug/net10.0/nettest.dll --sylux-muzzle-scene /tmp/prime-polish-netprofile 'MP1 SANCTORUS'`

`SyluxMuzzleTests` starts an asset-backed `ServerSim`, finds an actual room collision plane with the native `CollisionDetection` kernel, pins a finite muzzle interval crossing it, and places a damageable player beyond the plane. Local case invokes native `TryFireWeapon` with actual weapon inventory/cooldown; remote case admits a real fire event and runs native accepted-shot spawn. Each case processes production projectiles through `BeamProjectileEntity.Process`; no synthetic damage, hit claim, or paid physical witness is injected. Shadow proof remains the existing default. Controlled muzzle/body geometry replaces navigation/model animation, so this is a native kernel regression rather than a rendered movement or gun-model acceptance claim.

The gun draw anchor is 0.15 in front. Before log: `/tmp/prime-sylux-before.log`.

Lockjaw is tested through its actual `BombIntent` → native bomb admission → `SpawnBomb` path beside the wall. It creates a Lockjaw bomb and an unobstructed body-to-placement segment. Native Lockjaw uses a downward placement offset and radius/snare damage, so the fixture does not invent an alt-form beam action or claim muzzle parity applies to bomb splash. Bomb radius/snare mechanics across barriers remain a separate vanilla parity question.

## Correction

`BeamProjectileEntity.Spawn` tests the finite native `0x651/4096` muzzle-back interval for parentless Sylux beams whose authored weapon has `SurfaceCollision`. It uses the same map/closed-door/active-forcefield trace and impact resolver as ordinary flight. A detected obstruction resolves before instant area damage or homing acquisition. Native ammo gating/consumption, success feedback and shot/component identity remain in the normal spawn path. Ordinary guarded beams retain spread RNG, render-state initialization and muzzle association before impact; ricochet children are exempt. Other hunters and authored wall-piercing beams retain the normal path. Normal map collision retains its prior `noColEff` semantics.

This introduces no wire field, protocol number or enforcement-mode change. Reverting the localized spawn guard restores prior behavior; preserve the regression to expose the bypass. Shared trace/resolver extraction needs existing weapon/combat coverage in addition to this focused fixture.

After correction, root's coordinated current Debug run returned **PASS (27 assertions, 0 failures)** (`/tmp/fruity-sylux-after.log`). Both obstructed owner/remote targets received zero damage, while open and lateral controls retained their native positive damage; native Lockjaw placement checks passed. The same current build also passed **324 shot-proof scene assertions** and **94 combat-arbitration scene assertions**, providing broader native weapon/authority coverage of the shared trace/resolver extraction. Main and test builds were coordinated by root; the initial fixture-only builds used `BuildProjectReferences=false`. A nullable warning introduced by extraction is corrected by restoring the original `Debug.Assert(Owner != null)` invariant at the resolver entry, without changing behavior. Real GL gun-model presentation, alternative rooms, platform/device coverage, live owner/client routing and loss/jitter matches are not established by this controlled native fixture.
