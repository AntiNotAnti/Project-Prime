# RmlUi continuation: input, playback, virtual library and campaign routes

October 17, 2026. Local shared work based on `dc7f097067d755ec76d145fc7cc333068566863d`.
The user permits other implementation tasks to proceed in parallel and requires
new product UI to use RmlUi. CPP-01 remains **complete by explicit skip**.
These changes do not change the default frontend or certify untested devices.

## Implemented locally

- Desktop native input now connects the existing Windows, Cocoa and Linux IME
  adapters and gamepad navigation to the native document owner. Composition,
  focus epochs, Back, disabled controls and scene retirement are fenced.
  Transformed DOM bounds now agree with rendering and pointer hit testing.
- Native playback transport and camera input use the existing replay clock,
  scene and logical recording owner. Its transparent viewport preserves the
  rendered world. Rich cinematic editing remains an existing-owner handoff.
- The Lobby uses existing local PNG thumbnails through a bounded asynchronous
  PNG-to-TGA cache. Map changes clear old images; failures remain cosmetic.
  The left panel scrolls on short displays, so its actual preview remains
  reachable. No game thumbnail is bundled or generated by this adapter.
- Adventure pause now includes the discovered-only mission map and scan
  logbook. Sparse cartridge scan identifiers retain the existing discovery
  gates. The journal borrows only a detached snapshot and changes no save.
- Genuine ending receipts and shared credits have a native page with the
  existing campaign audio lease. Return consumes only the displayed receipt.
- Native gunship cockpit/star map uses the existing five-destination campaign
  navigation and Adventure launch owner. Opening, departure and final launcher
  handoff check the captured dock and exact saved-byte fingerprint. Returning
  to file select retains the genuine dock and permits native reopening.
- Native replay bookmarks support add, browse, jump and confirmed removal.
  Scene, logical/physical paths, recording stamps and annotation SHA-256
  protect the existing annotation writer.
- Native range marks, named highlights and virtual clip creation use the
  existing replay marks, annotations and virtual-clip owners. Read-only bar
  updates do not read/hash files each frame. Mutation requires the reviewed
  range and file witness; changed marks require explicit refresh.
- Native Theatre now discovers virtual clip descriptors, materializes them
  through the existing replay owner, and retains their logical annotation
  identity. Rename, organization, favorite and confirmed deletion operate on
  the descriptor/cache/sidecars; deleting a virtual clip preserves its source.
  Descriptor SHA protects same-stamp descriptor replacement. Physical-source
  freshness uses path, length and modification time, not a full source hash.
- Home now projects only matching-account, shared, unexpired friend presence.
  Unshared presence is never called offline. Cached Social/presence views carry
  an opaque internal auth-session lease; replacement or expiry clears private
  rows and retires late completions. Witnesses cannot serialize credentials.
- Native Community history exposes immutable revisions, exact historical
  installation selection and confirmed promotion through existing operations.
  Private history/creator rows retire with their account lease. A later
  visibility/lifecycle continuation remains under implementation.
- Materialized replay clips use the captured original transport and existing
  storage queue. Owner-thread completion handling fences stale routes and
  cancellation, retains failed inputs, and reports cancellation requests
  without claiming a completed output was rolled back.
