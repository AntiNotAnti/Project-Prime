## Proposed 10a boundary (design only)

A proven absence is the shared powerup receipt contract, not all pickup authority. Preserve the chronological source journal and existing health world lane. Introduce bounded authority-owned records keyed by match/epoch, player slot + life ID, stable spawn ID + spawn generation, and pickup request ID. Include requested contact/source frame and sampled position. Validate alive source history, contact/reach, active spawn lifetime, availability and current room. Atomically reserve/consume the spawn and append the grant to fire-time source history. Repeated requests return the immutable same verdict; refused requests cannot append a grant. Life change invalidates effect adoption, while bounded terminal receipts survive long enough to settle retries.

The client needs a separate bounded prediction book keyed identically. Predicted visual effects and predicted source permissions must be distinguishable from authority grants. On acceptance, hand over to authority start/end frame without restarting duration or replaying feedback; on refusal, undo exactly that prediction without deleting an independent later grant. Snapshots carry life-tagged effect generation and authoritative start/end (or remaining timer with server frame). Define overlap/replacement rules for Double, cloak and Death Alt explicitly. Do not infer contact from inventory or a frozen source journal.

## Proposed 10b boundary (design only)

Retain authority boolean freeze for compatibility while designing life-tagged effect generation and authority expiry. Convert native timer units explicitly: existing native timers count doubled 60 Hz values. Apply authoritative age from its server snapshot tick, never transport arrival alone; do not let an old thaw clear a newer freeze. Keep a separately tracked predicted Judicator generation until accepted/refused or reconciled by authoritative state. Preserve ice/sound start and thaw exactly once. Source-backed absence of a timer does not prove a measured player-facing regression; implement after the described lossy scene fixture establishes the expected behavior.

## Packet/replay migration and rollback contract

Any 10a/10b wire field requires the **then-current Prime protocol** increment, generated packet/codec validation updates, canonical replay capability/schema review, checkpoints/seek and join/bootstrap coverage. Do not adopt Fruity 30 or assume the next number before rebasing. Keep older replay reading through `ReplayIdentityCompatibility`; if a new effect cannot be inferred from older recordings, declare the capability absent rather than inventing grants. Test truncation, excessive receipt counts, stale match/life/generation, duplicate IDs and malformed timers. Keep realtime datagrams within the existing 1200-byte lane by budgeting or separate bounded packets; never grow the canonical 4096-byte buffer into one live datagram.

New enforcement must be default-off with explicit telemetry for accepted/refused/dedup/stale-life/prediction-handover outcomes. Shadow evaluation must not create real effects. Rollback flag disables new enforcement/adoption inside compatible builds; reverting an incompatible wire change requires draining admissions and coordinated matching server/client deployment. Replays already recorded with new capabilities still need a retained reader.

## Follow-up source inspection and concrete successor schema

Pinned Fruity source confirms the boundary directly: `NoxusIceWaveFreezeSync::Capture` caps `ModFrozenFrames` into one byte; `Apply` calls `ReconcileFreeze(authority frames, local frames, Awaiting(slot))`, then mirrors/ends/keeps the effect. `NetPickupClaims::Declare` records slot generation, life, spawn ID and spawn count; `Judge` checks contact age, spawn appearance, item availability and historical reach before `OnPickedUp` plus `NetPowerUps::Grant`. `Receive` caches the verdict for duplicates; `NetPowerUpPrediction::Settle` delegates a life-aware rollback and restores only the returned effect timer. These are concrete behaviors to reproduce, not a requirement to copy Fruity's ring/dedup implementation.

There is **no safe protocol-50 reserved-field implementation** for exact freeze timer. All current `PlayerState.Write` bytes are occupied (`NetProtocol.cs:1909–1936`); six unused auxiliary flag bits cannot represent the normal 0–150 native freeze countdown. Repurposing other state bytes would corrupt unrelated behavior and is still a semantic wire change. Prime fast lane currently peaks at **1172 bytes including header** (`ContinuousSnapshotTests.cs:36`), leaving 28 bytes at 8 players.

A concrete migration candidate for 10b is a three-byte `FreezeState` record (`ushort EffectGeneration`, `byte RemainingNativeTicks`), appended after the current form suffix in canonical PlayerState. The fast lane must explicitly copy this suffix because it currently copies only `Protocol48Size` and omits form (`NetReplicationLanes.cs:10,19–21`). Three bytes × eight players yields **1196 bytes**, within the 1200-byte bound. Preserve existing life/generation fields and `SnapshotHeader.Frame`; validate timer <=150 for current native rules instead of silently truncating larger future timers. If another change consumes this headroom, use a separate bounded effect lane. This is a design budget, not a measured datagram or accepted implementation.

Use distinct constants for the frozen protocol-50 player size and the successor size. Update canonical Write/Read, fast player size/copy offsets, snapshot validation/composition, bootstrap bounds, authority capture, live receiver, replay conversion and `ReplayIdentityCompatibility` expansion. Convert old canonical/fast records by appending zero effect capability while retaining legacy boolean handling; do not reinterpret old timerless replays as exact reconciliation. Preserve old form offsets explicitly. Add successor capability metadata and checkpoint timer/generation/prediction ownership. Wire successor handshake is required even with enforcement flag off.

Runtime design: increment effect generation only on authority freeze starts/re-freezes, clear per-life state at spawn, compare `(match, epoch, slot generation, life, effect generation)` before adoption, age remaining native ticks against authoritative server frame using explicit 2-native-ticks/60-Hz-step conversion, and reject old thaw/generation snapshots. A default-off `PRIME_FREEZE_RECONCILIATION=1` would govern adoption; capture/codec remains part of the successor protocol. A predicted generation must not become authority-owned without a matching grant or snapshot, and expiry must play thaw effects once. Required tests include 150-tick first freeze, 30-tick quick re-freeze, late/reordered snapshots, predicted freeze before authority snapshot, old-life packet, seek/bootstrap and 8-player maximum size.

10a cannot be represented honestly by the existing health picker fields: health-only registration excludes the three powerups, picker slot omits life/effect identity, and spawn availability cannot express refusal or replacement grant duration. Introduce distinct bounded pickup claim/verdict records and effect state lane, with packet-size accounting and recorded replay semantics. No production correction is applied here pending the coordinated wire/replay migration.
