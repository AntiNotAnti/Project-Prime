# Native Adventure save copy and archive

The native three-slot Adventure page now offers a copy destination and explicit Copy and Archive confirmations. The confirmation captures the complete displayed source/destination metadata and SHA-256, including an occupied unreadable destination or an empty slot. Unavailable identities never authorize a change. Copy requires a readable source; Archive may preserve unreadable raw bytes without parsing or normalizing them. Empty slots cannot be archived.

The existing `AdventureSave` owner provides guarded `TryCopy`/`TryArchive` operations. It keeps the established native save location and byte representation, backup naming and `Menu.SaveSlot`; neither the presenter nor controller serializes a `StorySave` or changes gameplay state.

Copy hashes a staged source before mutation and rechecks the captured source and destination. An occupied destination moves into an unused backup with no overwrite, then the moved backup is verified. Publication moves staging only into an empty destination with no overwrite. If publication fails, only this invocation's moved backup may be restored, and only into an empty destination. A newly created/raced destination or an earlier backup is never replaced by that recovery. Archive moves the actual slot into an unused no-overwrite backup. Both operations verify the resulting byte identity before reporting success; unknown outcomes remain explicitly unverified with recoverable bytes preserved.

The management gate serializes these management operations inside the process. Hash preflight and publication are **not** cross-process compare-and-swap: an external writer can change paths between checks. No-overwrite moves and retained backups prevent this code from discarding raced bytes, and readback refuses to claim a verified result when observed identities differ. A failed operation may leave a recoverable backup; it never silently retries a mutation.

The final existing `StartScreen`/`Shell` owner admission rejects active scenes, sessions/replay, startup/finished/overlay state, pending or failed post-match commits and outstanding save requests. It rechecks complete slot metadata and fingerprints immediately before the guarded byte operation. `MatchStart.HasPendingCommit` is read-only; management never retries/releases a pending save. The `StorySaveCommit` serializer and format are unchanged.

Save management opens in RmlUi without requiring cartridge assets. Campaign launch, Resume and New Run retain their file admission. Confirmation uses the existing native modal manager and document/sequence/foreground fences. Cancel, Back, refresh and route retirement discard captured proposals without calling the writer. A consumed confirmation cannot repeat its effect, including on refusal. The new finite intent kinds are appended at 127–132; existing values remain unchanged.

`tools/rmlui-adventure-save-check` links the actual byte owner/draft source and passed 33 checks using temporary raw files and unrelated engine symbol stubs. It tests exact-byte copies, unique retained backups, unreadable archive, empty/unavailable identities, stale metadata, blocked publication, backup exhaustion, staging cleanup and once-only/cancelled/refreshed proposals. No save serializer, real user-data path, scene or cartridge assets are used.

`AdventureSaveAcceptance` extends the composed managed menu fixture with synthetic service authority. `AdventureSaveGlAcceptance.Run(host,width,height)` exercises real authored native buttons/modal/focus with synthetic slot data and an in-memory effect owner. Those fixtures require the next centrally coordinated main/native/tool build. Their pending 640×360, 1280×720 and 1920×1080 acceptance does not certify a real campaign or device save flow.

The initial immutable RML58 640×360 native run reached the real Copy and Cancel buttons, then failed its combined proposal-retirement/focus/no-write assertion. Source inspection identified restoration ordering: the modal manager attempted to focus Copy while the old parent binding still disabled it. The Adventure adapter now remembers the opening action and restores it through the existing post-update focus path, after fresh parent bindings apply. When the resulting action remains disabled, such as Archive on a newly empty slot, it restores the selected slot instead. The source-linked runtime fixture passes explicit deferred-focus and consumed-restoration regressions. Native reruns remain pending; the initial failed checkpoint is preserved.
