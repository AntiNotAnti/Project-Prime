# SH-03: transactional character authoring previews

The existing Retro exporter now publishes one private immutable bundle per supported appearance, reusing its verified source readers and model/rig/motion conversion. Each bounded schema-1 receipt records the canonical appearance ID, exact verified archive-inventory fingerprint, common recipe version/hash, and each output's size/SHA256. Required geometry, skeleton, weights and motion sidecars must all exist; optional raw ANCS graph proofs join the same generation. Ready means complete authoring input, never a playable character. Materials, ball, cannon and full playable animations are not fabricated.

The existing native Settings controller, file picker, background-operation owner, stage/cancel control and confirmation dialog now provide appearance selection, Check, Update selected, Update all from the selected source game, and Remove. Update all parses selected appearances first and commits one complete independent appearance at a time; cancellation can leave previously completed appearances updated. A recipe update rebuilds the complete selected appearance. Read-only Check runs off the UI thread. Retired controllers reject late picker completions. No renderer, global skin replacement, source download, Community package or online identity is introduced.

The bundle owner accepts narrowly validated flat json/obj/bin/glb artifact names, with existing 64 MiB/component and256 MiB/bundle limits. It rejects paths, empty segments, uppercase/non-ASCII names and Windows device filenames. Remove takes the same permanent cross-process writer lease and atomically renames the current receipt to a unique retired receipt. Retained generation bytes remain valid for existing consumers. Repeated removal is harmless; reinstall can reuse verified retained bytes. Removal never deletes source media or unmanaged artist exports and does not promise disk reclamation.

Sequential batch publication reports committed canonical IDs on a later cancellation or failure. Source-free tests cancel immediately after the first real bundle commit and verify the second bundle retains its old good generation; Settings preserves the partial outcome instead of claiming nothing changed.

Existing schema-1 Echoes receipts remain supported. Legacy loose character exports are retained as unmanaged artist files; the new inventory does not silently adopt them. Authoring tools should receive the generation directory containing the printed OBJ path. Runtime CPP acceptance, native parent fallback, seven Hunter identities, live protocol61 and replay formats are unchanged.

Validation and exact frozen-source results are added below after reruns. Physical Windows/Android import UI, Android storage URIs, crash/power-loss durability, full body/skin/ball/gun/material readiness, per-component recipe upgrades and coalesced cancellable cross-process waiters remain unverified or unfinished. Busy writers fail promptly; immutable generations and retired receipts remain on disk. Rollback: restore an older retained receipt with matching code, or revert this importer and reexport using that version; never delete data used by a live scene. No release qualification is claimed.
