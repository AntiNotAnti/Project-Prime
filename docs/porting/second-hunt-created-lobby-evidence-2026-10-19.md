# SH-06: retire stale created-lobby client handoffs

A committed directory allocation may finish after its original native menu is canceled or disposed. Previously its worker could still initialize a client, save hosting preferences and broadly stop sessions on failure. Created-lobby admission now reuses NetClientJoinOwnership, the existing NetLaunch initializer fence and owner-thread acceptance. A registered attempt binds its cancellation source, exact Lobby reference, transport incarnation and detached preference receipt. Only an accepted current attempt writes preferences. Cancel, stale completion and direct service teardown retire that attempt's client ownership; replacement clients and dedicated authorities survive. A disposed service cannot register another attempt.

Native PlayCancel now retires the client handoff and permits retry. A committed remote allocation finishes its reply before checking cancellation, then cannot initialize a retired client. No player-authority fallback, packet, identity, map admission, party reservation, session cycle or replay format changes. Returned admission tokens are never added to telemetry or preference receipts.

LocalServer serializes its existing startup owner. Local creation acquires that same gate, checks cancellation before allocation, then finishes the bounded child startup independently of UI cancellation and snapshots that start's port/owner token/error under the gate. It checks cancellation again before client connection. Explicit Stop and process detach share startup synchronization. This prevents canceled/retried creation from observing or stopping a newer singleton startup. Successfully allocated dedicated children retain their existing independent lifetime; client cancellation does not kill them or a shared daemon. Remote pools retain their existing unused-child reaper policy.

Tests cover exact menu validate/accept/note ordering, canceled queued success, immediate retry and stale completion; actual live service plus content-free playback transport cover exact Lobby identity, transport replacement, authority replacement, cancellation/disposal and deferred/one-shot preference writes. A held real LocalServer gate and pre-canceled Start prove no child/token/library changes or source access before a retired queued startup exits. This is ownership/lifecycle evidence, not a real allocator/server deployment or gameplay test.

The complete SH-06 directory-owned grouped search, mode/region/content query, pre-allocation ballot, queue telemetry and deployment load acceptance remain unfinished. Existing party reservations require a leader already admitted to a lobby. This slice does not represent solo Random Match as group matchmaking or activate a new directory path. Rollback is a self-contained revert of this lifecycle slice; dedicated server authority and existing cancellation/admission owners remain. Frozen build/test results follow after verification. Per user instruction merge follows local checks without waiting for review/CI; CI is not claimed green.
