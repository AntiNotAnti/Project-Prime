# Competitive balance change record (schema 1)

Status: **proposal only**. No tuning is authorized by an automatically generated report.

- Record ID / revision:
- Owner / reviewer:
- Hypothesis: one falsifiable statement, including the affected Hunter, weapon, mode and map population.
- Metric: exact numerator, denominator, exclusions and telemetry coverage. Distinguish pickup frequency from weapon availability/control time.
- Baseline: immutable report hashes and UUIDs, cohort hash, build/content/rules versions, time window, sample sizes and uncertainty. State guest/bot/Practice exclusions and authentication provenance.
- Change: exact versioned parameter delta; only Competitive unless explicitly approved otherwise.
- Validation window: start/end, required matches and participants, matched comparison population, minimum coverage, stopping rules and independent review. A descriptive minimum count is not statistical significance.
- Rollback condition: quantitative regression limits, safety triggers, rollback build and owner.
- Result: observed effect and uncertainty; retain negative findings and failed hypotheses.
- Decision: reject, extend measurement, or approve separately. Record approval and deployment evidence separately from test evidence.

Do not combine incompatible content, rules, builds or server trust populations. Do not attribute participant totals to a Hunter when that participant changed Hunter. Do not infer physical map-side bias from team indices without verified side assignment. Do not replace missing telemetry with zero. Do not use this record to justify an unmeasured health, damage or movement adjustment.
